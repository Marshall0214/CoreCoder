# 最终补丁公开语义验收事务 v1

## 本轮解决的问题

此前事务仅验证唯一文本匹配、Python 编译、重复定义和实际模块加载，结构合法的错误补丁仍会写回，再由公开检查发现失败。新增 [语义验收事务](experiments/semantic_patch_transaction_v1.py)，把公开行为验收移到原文件写回之前。

流程为：复制工作区 → 在候选副本中应用结构事务 → 在另一个副本运行固定公开检查 → 检查候选、原文件与公开代码未发生变化 → 写回准确验收过的候选。任何公开断言失败、候选异常、检查故障、超时、跳过、零测试或执行数量不符，都不写入原工作区。失败诊断、候选源码和测试记录保留在事务输出目录。

内部结构事务的 `accepted` 只表示候选副本应用成功；外层 `accepted / committed` 才表示原文件提交成功。提交发生写入异常时尝试恢复已写文件，并记录恢复结果；恢复失败明确返回 `rollback_failed`，不能宣称原文件保持不变。

调用方提供固定公开检查路径、原始代码哈希、检查目录哈希及任务身份，模型不能选择验收代码。仅支持一个 `PublicContract` 类中明确声明的唯一 `test_` 方法；执行数量必须与静态数量一致。公开检查和事务输出必须与源码分离，检查目录只能包含与规范文件字节一致的 `test_admission.py`。

人工正例使用完整修改文件作为离线编辑证据；历史模型重放保持原来实际提供的局部证据。完整文件正例不作为模型检索策略、Token 预算或修复率证据。

本轮 **0 次模型请求、0 次私有评分请求**，冻结引擎哈希不变。三份错误被拒绝是已知补丁的离线拦截结果，不是新的任务修复成功率，也不证明任意错误都能被公开检查发现。

## 接入边界与下一步

这是可调用的事务原型，尚未接入默认 API 或模型 Worker。拒绝时保留的是本次事务进入时的源码：历史重放中它是第一轮候选，不能说已恢复整个任务开始前的状态。事务本身不申请额外模型调用或重试。

下一步接入统一反馈实验：第一轮只保存在暂存候选；反馈仍使用当前版本证据，最多两次请求共享预算；最终候选通过语义验收才进入任务工作区，失败保留诊断并恢复任务起始状态。先验证这些生命周期状态，再决定是否开展新模型对照。

调用方需要独占工作区。该实现不是跨进程锁、崩溃安全的多文件原子提交或操作系统沙箱；公开检查通过也不等于完整上游测试或生产正确性。默认服务与历史模型策略未修改。
