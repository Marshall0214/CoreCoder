新编码只在旧字符串共享仍超限时启用，进一步共享重复的 JSON 对象/数组及其嵌套正文；编码有显式名称和引用，并验证完整还原。原有编码格式仍可读取。它保留每份公开轨迹、错误和代码文本，不声称所有长轨迹都能装入固定窗口；目前 **3/4** 保存案例通过传输回放，不等同于这三项已经修复成功。

## 2. 为什么丢失 more-combination-index

真实轨迹显示：

1. `base1` 初始补丁即通过公开检查，反馈修正次数 0；`inv1` 也通过了公开检查。
2. `agg1` 在旧循环前增加了元素存在与顺序检查，但保留了错误的索引计算，公开复现仍失败（`AssertionError: 2 != 1`）。
3. `agg1` 的前 4 轮反馈都因补丁 JSON 不符合约定被拒绝，第 5 次请求发生 provider failure，未得到可用修正。连续原生输入计数为 32,770，完整文件上下文存在容量风险，但目前不足以把格式错误或超时精确归因为服务端截断。
4. 官方 parallel k=1 最终只把 `agg1` 放入最终池，按“已交付”自动采纳，未与 `base1`/`inv1` 比较公开检查结果。因此候选生成失败与交付规则缺口叠加，覆盖了已有的公开有效候选。

这不是“没有再加一轮修正”，也不是“独立评分选错了”；原流程没有保留已通过公开检查的候选。

## 3. 已新增的可选交付规则

控制端 `public-preserve-v1`：优先采用公开通过的 `agg1`，否则按固定顺序 `base1 → inv1 → dom1` 查找公开通过的候选。只使用同任务、同源码和同公开检查配置的终态报告，核对最终工作区哈希、检查哈希和包含非空 Reproduce/Preserve 的匹配验证收据；过期或篡改的成功记录不能用于替换候选。

若没有公开通过候选，保留未损坏的官方结果供独立评分；若官方结果也不存在，则仍报错。这项规则不会把前述 6 项流程错误自动改成成功——离线回放中，它们均没有可用的公开通过候选。

这是本项目新增的控制端交付策略，**不是官方 selector 投票**，也不保证独立测试通过。默认仍为 `official`；新实验通过 `--candidate-policy public-preserve-v1` 显式启用，并写入新协议；不允许修改已冻结批次的策略。

在 `more-combination-index` 的保存制品回放中，新规则独立选择了 `base1`，随后才执行 Docker 独立验收：**Target 1/1、Controls 1/1，通过**。没有人工改补丁、没有新增模型调用。它证明本例可通过候选保留避免成功丢失，**不将旧 27/50 改写为 28/50，也不报告新策略的完整通过率**。
