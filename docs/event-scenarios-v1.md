# 事件检查的契约对比场景

## 实现与离线验证

新增可选 `--public-check-policy contract-scenarios`，协议为 `public-contract-feedback-v6-scenarios`。继承 v5 的导入限制、接口/契约目录审查、Schema、算术校验和参数状态观察过滤；仅追加通用生成指导：按契约设计跨作用域共享标识、重复输入后仍有新输入、持久状态跨调用重放等对比场景。仅当公开契约支持相应行为时使用，不按任务 ID 分支，不读取隐藏测试或参考补丁。

提示要求通过返回结果观察行为；对可能随后变更的平坦容器立即复制快照，避免断言先前返回值实际已被下一次调用修改。调用状态与断言快照名称分开，防止合法重放测试因直接检查传入状态而被 v5 的保守规则过滤。该提示是指导，尚未强制模型覆盖全部场景。

依据公开 events.md 编写三项独立回归示例：跨租户同 ID、批次中途重复后追加记录、跨调用重放旧记录并追加新记录。只检查 API 返回值，不检查 seen 表示。这些手写示例不进入模型请求，也不代替模型生成的检查。

v6 的多租户用例用了不同事件 ID，没有执行提示要求的跨租户同 ID 对比。两项跨批次用例直接断言 state，仍被保守观察规则排除。因此目前只解决“提前停止”这一检出缺口，跨租户身份和跨批次覆盖仍未完成。审查没有拒绝保留检查，公开检查与正确修复也没有发生冲突，但这些事实不能证明所有契约都覆盖或期望都正确。

下一步采用带契约来源的结构化场景清单，记录要求、实例化方式和未实现项，再生成检查；验证最终用例是否实际包含所需输入对比与返回值快照。清单及静态校验依然是覆盖诊断，不作为语义证明；不得按隐藏验收结果挑选检查。完整覆盖和可靠性确认后再研究按需验证成本，暂不推广默认。

```powershell
python -m pytest tests/test_check_scenarios.py tests/test_compare_workflows.py -q
python -m pytest tests -q
python -m docs.scripts.compare_event_scenarios --output .tmp/evals/event-scenarios-v1-replay
```

必须使用新目录。脚本会冻结版本并保留全部失败，不以单次通过为批次完成标准。原始实验、故障拆分日志和质量诊断在被 Git 忽略的 `.tmp` 中，需另外备份。
