# 任务级暂存反馈与语义发布 v1

## 接入后的行为

上一轮语义事务只能保护“事务开始时的源码”，历史重放时它已经包含第一轮错误修改。本轮新增 [暂存反馈 Worker](experiments/tentative_feedback_worker_v1.py)，把保护范围提升到整个任务：

1. 记录任务起始文件字节，复制到独立暂存区。
2. 复用冻结的统一反馈流程，只修改暂存区。第一轮可以暂时失败，第二轮使用当前版本片段和已编辑函数原文，最多一次反馈。
3. 从任务起始源码与最终暂存候选计算净修改，在独立候选中重新编译、导入并运行认证公开检查。
4. 检查通过后才发布到任务工作区；检查失败、第二轮无效补丁、预算停止或模型调用异常时，保留候选和诊断，不发布第一轮或第二轮修改。

净修改的完整文件锚点由程序从两个本地快照计算，仅用于最终提交，不提供给模型扩大上下文。模型仍使用冻结的唯一片段编辑协议、6,000 字符与五函数上限；最多两次请求，共享 15,000 Token。未采用上一轮收益为负的结构化假设提示。

生命周期记录为 `tentative → feedback_finished → validating → committed / rejected`；预算或调用异常可以提前 rejected。顶层 `committed`、`edited_files` 表示任务工作区发布结果，嵌套 `attempt` 里的编辑与结构事务成功仅表示暂存候选。

失败时任务起始版本通常从未被写入破坏，因此不依赖事后覆盖来“恢复”。最终提交发生写入异常时复用语义事务的恢复机制；恢复失败会明确记录。外部并发修改会停止发布并保留外部修改，不强制覆盖成任务起始字节。

## 离线生命周期重放

[重放入口](experiments/tentative_feedback_audit_v1.py) 读取冻结的已编辑函数实验中，两项 `edited-first` 分支的真实回答与 usage，重新执行公开观察、两轮编辑和最终发布。没有新模型推理，没有私有评分请求。

| 任务 | 重放回答 | 最终发布 | 任务工作区 |
| --- | --- | --- | --- |
| click-usage-empty | 两轮 | 通过，发布正确净修改 | 与历史正确候选字节一致 |
| itsdangerous-none-salt | 两轮 | 公开检查失败，拒绝 | 与任务起始版本字节一致 |

四次请求的输入除公开 unittest 耗时行外与历史相同；本次三次原始提示哈希相同，一次仅归一化 `Ran N tests in X.XXXs` 后一致。测试数量、失败内容、源码片段、函数版本、系统指令和其他字段必须保持一致。最初严格重放因耗时差异失败，其未完成记录保留；正式记录为 `.tmp/real-defects/tentative-feedback-audit-v1-final`。

这里的 usage 是历史数据，用于重放累计预算约束，不是新增 Token 消费；重放速度不能与真实模型耗时比较。两项任务及回答都已查看，该结果是流程验收，不能称为新修复率、泛化评测或模型能力提升。

## 软件验收

新增 16 项测试，覆盖首轮正确直接发布、公开失败的一次修正、候选异常修正、结构失败修正、最终失败保持任务起始字节、预算停止、调用异常、无认证检查提前停止、规范检查变更、外部源码变更、提交恢复，以及只允许公开耗时行归一化。

测试在两次模拟请求内部直接断言任务工作区仍是起始源码，确保第一轮修改没有提前发布；第二轮同时核查模型看到的暂存原文，验证上下文版本正确。专项 **16 passed（4.39 秒）**；Windows 全量 **1,112 passed、2 skipped（167.65 秒）**，完整回归见 [机器摘要](tentative-feedback-v1.json)。本轮未重跑 Linux、Docker 或 HTTP。

## 当前边界与下一步

已接入可选实验 Worker，尚未接入默认 API、服务调度器或真实新模型对照。只处理已有认证公开检查的任务；缺少认证检查时停止，不默认降级为无语义验证提交。公开检查通过仍不等于完整上游或生产正确性。

调用方需要独占任务工作区，源码与输出目录分离；没有跨进程锁、崩溃安全多文件原子提交或操作系统沙箱。急停发生在最终多文件写入期间仍受该边界限制。源文件与诊断保留用于核查，不在本轮自动删除。

下一步用固定模型与预算对两项真实任务开展全新对照：比较任务发布结果、失败时源码保护、额外公开检查耗时及 Token。通过后再决定如何接入服务，不能把离线重放写成新模型收益。
