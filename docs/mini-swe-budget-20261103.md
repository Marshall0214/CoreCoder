# mini-SWE-agent 单项预算诊断：Click

## 问题与结论

上一轮五项均在编辑原有源码前停止。这次只选择预先确定的 `click-usage-empty`，将累计 Token 预算由 30,000 调至 100,000，其余配置保持不变。

**新候选通过独立验收：目标测试 2/2、正常行为测试 2/2。** Agent 在第 15 次调用修改源码，第 16 次执行自测；请求第 17 次调用前预算不足而停止，未主动提交。
因此结论是“终止时已有通过约定独立检查的候选”，不是“Agent 已完整完成提交”，也不是完整上游测试通过。

## 不变条件与可比性限制

- 同一个公开任务、基线文本文件及内容哈希；同一个 Qwen3.5:27b digest、think=false、temperature=0。
- 上游 DefaultAgent、配置模板、文本解析与执行适配器未变；隐藏评分始终在终止后进行。
- 最多 20 次请求、1200 秒、输出最多 2048 Token、估算上下文上限 16k；已有禁网 Docker 镜像、资源和评分规则均未变。
- 新增 `--token-budget` 显式参数，默认仍为 30000；本轮唯一改变的运行配置字段为 `token_budget`。这是我们选择的诊断预算，不是官方默认值。
- **执行环境不保证目录枚举顺序。**两轮首次模型输入和首次模型响应完全一致，但首次 `find ... | head -50` 的输出顺序不同，第二次请求起上下文及行为路径分叉。完整轨迹不是确定性重放，不能把新增成功完全归因于预算，或当作统计显著提升。

本轮证明在这一配置下本地模型能够生成通过检查的候选，并进一步执行验证；原 30k 条件确实提前限制了探索空间。尚未证明它必须消耗 90k、其他任务也能改善，或应该提高所有任务的默认预算。

## 实际执行与补丁

1. 第 1–10 次定位、读取 `write_usage` 与相关测试。
2. 第 11–14 次运行边界复现并继续确认原实现；其中一次命令失败后自行修正。
3. 第 15 次通过 Python 脚本替换 `write_usage`，仅修改 `src/click/formatting.py`。
4. 第 16 次再次执行模型自测；随后累计已用 90,624 Token，剩余 9,376，下一次输入估算 11,129 Token，故预算预检查拒绝继续。
5. 容器导出并清理；控制端独立运行原有 Target/Controls，均通过。模型没有看到独立评分结果。

补丁将“程序名后的空格”移动到非空参数分支；空参数时直接写入使用说明前缀与程序名，避免多余尾空格，并保留非空参数的折行处理。
补丁是否符合完整上游行为仍需更广回归，当前结论仅覆盖约定的两组检查。

Langfuse 回读 16 个真实 Generation，输入 87,800、输出 2,824，与本地实测一致；记录均已结束。未使用付费 API、未下载镜像、新数据均在 D 盘。
