# Langfuse 本地服务上线与回读验收

**结论：服务已上线，完整工程演示通过。**这是上一阶段[可选追踪接入](langfuse-20261029.md)的部署续验收；没有调用模型或改写历史修复率。当前地址为 `http://127.0.0.1:3300`，登录信息保存在项目 D 盘 `.tmp/langfuse-local/login.txt`，不进入 Git。

## 完成的链路

```text
可信合成 Issue → CLI / API → 审批与恢复 → 只读依赖读取 → 受限补丁
             → Docker 公开检查 → ready_for_review + 本地证据
             → SDK → 本地 Langfuse → 独立回读确认
```

CLI/API 产出相同补丁，重复提交、重复审批和拒绝行为通过；两次执行均为脚本响应，真实模型调用 **0**，`accepted=false`。公开检查成功不等于真实 Issue 的独立正确性验收。

服务器中共回读 **2 条 Trace、14 个节点**，每条为：1 个任务根节点、2 个脚本响应、1 个符号读取、1 个补丁调用、2 个 Docker 检查。逐类数量与本地 `trace.jsonl` 一致，全部有结束时间，子节点绑定正确根节点。三项评分分别为公开检查通过、独立验收不可用、模型调用数 0。输入输出使用白名单摘要，无源码、Prompt、替换片段或原始测试日志。

SDK 原始报告仍记录 `submitted_unconfirmed`；[独立服务器回读](langfuse_server_20261029/server-receipt-final.json)确认存储，不篡改原始执行状态。停止并启动本项目全部六个容器后，原 Trace、节点及评分仍可读。生成的本地账号通过会话登录验证，密码和 Cookie 不进入证据包。

## 部署问题与修复

1. **下载频繁 EOF / TLS 中断：**使用用户提供的本机代理 7890，从官方 registry 分层断点续传、刷新过期匿名拉取令牌；核对层大小和 SHA-256 后导入。保存了官方 manifest digest、Docker 镜像 ID，以及四个新增导入镜像的文件系统层一致性结果；不降低 TLS 或 digest 校验。
2. **对象存储端口不可绑定：**本机 Windows 保留了 3307–3406，原 3390 被拒绝。改为已验证可用的 13390，现有密码保持不变；准备脚本默认值同步修正。
3. **首次启动迁移竞争：**Worker 曾先于 Web 完成数据库迁移，出现临时缺表错误。增加 Web 健康检查与 Worker 就绪依赖。当前镜像的服务监听容器地址，健康检查改用 `web:3000`，实际测试为 200；容器内 127.0.0.1 曾返回连接拒绝。
4. **逻辑根节点误判：**SDK v5 使用指定 Trace ID 时，逻辑根节点可能保留外部物理父节点。回读脚本依据服务器 `isRootObservation` 识别，仍拒绝环和错误子节点归属；补充缺少重复操作、未结束、评分缺失与非摘要内容等负例。

最终六个服务均 running；Web、PostgreSQL、ClickHouse、Redis、MinIO 健康检查通过，Worker 等待 Web 健康后启动。仅发布回环地址上的 Web 3300 和 MinIO 13390，数据库不发布宿主机端口。未重启 Docker Desktop、未修改全局代理、未操作原 8001 服务。卷、下载、依赖和任务产物均在 D 盘。
