# CoreCoder 扩展项目：阶段收尾

更新：2026-10-09。本阶段完成交付整理，停止已知失败案例专项调参；未新增模型调用、修改默认 Agent/API 或运行部署。

## 做成了什么

从上游 CoreCoder 的通用工具调用循环出发，新增可信任务契约、独立工作区、代码检索、结构化补丁、验证与失败反馈，以及本地任务服务。个人贡献是这些扩展；基础 Agent、模型接口及既有工具保留上游归属。

| 成果 | 可核查证据 | 实际范围 |
| --- | --- | --- |
| 缺陷修复评测闭环 | [完整对照](system-comparison-v1.md)、[逐项数据](system-comparison-v1.json) | 5 个仓库、50 项已知缺陷，多数单文件；目标与正常行为独立检查 |
| 检索、补丁和反馈流程 | [完整对照执行器](experiments/system_comparison_v1.py) | 符号/类范围检索、唯一锚点补丁、公开验证、最多一次修正、失败回滚；独立实验入口 |
| 本地工程入口 | [演示指南](demo-guide.md)、[服务说明](service-mvp-v1.md) | FastAPI、SSE、幂等、取消、SQLite、LangGraph 审批/恢复；可信任务目录 |
| 工具与部署 | [MCP](mcp-code-knowledge-v1.md)、[容器验收](container-deployment-v1.md) | 只读代码知识 MCP、Docker/Linux 单服务；不是生产级任意代码沙箱 |

## 能说明效果的数据

同一模型、50 项任务、统一评分和相同每任务预算上限，一轮完整对照：

| 指标 | 单次检索修复 | 验证反馈流程 |
| --- | --- | --- |
| 统一验收通过 | 25/50（50%） | 32/50（64%） |
| 模型调用 | 50 | 71 |
| Token 总数 | 143,193 | 216,492 |
| 最终正常行为检查通过 | 48/50 | 50/50 |

新增 7 项成功、丢失 0 项，修复率提高 14 个百分点，Token 增加 51.2%。两组首轮请求和回答全部相同，改进来自后续流程；额外一次修正增加实际计算量。正常行为 50/50 包含失败回滚后的结果，不表示 50 项全部修好。

这是人工构造的已知任务池、单轮探索性实验，不能声称 SWE-bench、全新盲测、统计显著或优于 Codex/Claude Code。历史受控七工具组预算停止情况不同，不把它的 0 项正常完成包装成“0% → 64%”。

## 为什么现在停止

完整流程仍有 18 项失败。后续局部试验出现过单项改善，但没有重新证明完整任务池提升；最近运行事实对照仍 0/2 → 0/2，人工候选 2/2 不计入 Agent 成绩。继续针对相同案例调参容易过拟合，边际收益已不足以支持扩展。

保留实验代码、失败分析和成本记录，未证明收益的策略不叠入默认流程。详细记录见 [两例报告](two-case-runtime-v1.md)、[失败审计](remaining-failure-audit-v1.md) 和 [历史归档](core-repair-history.md)。默认服务与 50 项实验脚本仍是不同入口。

## 简历可用表述

**CoreCoder 扩展：代码缺陷修复与验证系统（个人项目）**

- 基于开源 CoreCoder 构建缺陷修复评测闭环，整理 5 个 Python 仓库的 50 项真实来源缺陷，隔离修复工作区与独立评分，记录补丁、Trace、Token 和失败原因。
- 实现符号/类范围检索、唯一锚点补丁、公开测试反馈及失败回滚；在固定模型与统一评分的 50 项完整对照中，通过数由 25 提升至 32（50% → 64%），新增成功 7 项、无成功丢失，Token 成本增加 51.2%。
- 开发 FastAPI 本地任务服务，支持幂等提交、SSE 状态流、取消、SQLite 持久化及 LangGraph 审批恢复；接入只读代码知识 MCP，完成 Docker/Linux 部署验收。

面试解释：项目用于实践可替换的修复流程和可复核的评测，不主张替代成熟 Coding Agent。模型负责候选生成，系统负责组织证据、验证结果和保留失败；服务目前限制可信任务，尚未支持任意 GitHub 仓库。

## 交付前最后的使用步骤

1. 按 [演示指南](demo-guide.md) 演示提交、审批、重启恢复、验证和防重复执行。scripted 演示明确是工程链路演示，真实模型效果展示完整报告。
2. 准备一个成功补丁与一个失败回滚的证据，说明系统如何区分“生成了代码”与“通过了验收”。原始日志位于 D 盘 `.tmp/`，分享前检查敏感信息；Git 不包含全量原始输出。
3. 使用上面的三条简历表述，根据目标岗位缩减内容。录屏、对外发布与投递尚未执行。
