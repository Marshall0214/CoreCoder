# 从起始源码重新修复：配对实验与停止结论

本轮尝试丢弃错误候选后重新修复，结果为继续修改候选 **1/2**、起始源码重启 **0/2**。不采用、不扩展任务集，不修改默认 Agent 或服务。完整配置、用量、事务、评分和来源哈希见 [机器摘要](restart-feedback-v1.json)。

## 策略与实现

第一轮提示和工具集合不变。公开检查确认候选失败后，原组继续编辑当前候选；实验组保留公开失败输出及公开测试代码，将实验工作区恢复到起始快照，刷新源码证据和文件哈希，再用同一片段替换协议生成一次修复。

反馈明确标注失败输出来自已丢弃的候选，展示片段是任务起始版本。未额外展示候选源码或补丁历史；该版本检验的是“保留失败观察、重置编辑起点”，没有同时引入历史上下文变量。事务失败且未提交的初始补丁仍使用原结构反馈，不触发源码重启；首轮通过公开检查时不重启、不增加请求。

[Worker](experiments/restart_feedback_worker_v1.py) 保存精确字节快照。回滚前确认候选未被外部修改，只支持原有文件且修改均在允许范围内；否则停止并保留当前内容。回滚验证全量字节与起始快照一致，写入异常时尝试恢复候选字节。此为可丢弃实验工作区上的保护，不能宣称支持并发共享仓库或崩溃原子事务。第一轮回答、事务与公开失败日志均保留在输出目录。

## 配对条件与结果

[配对驱动](experiments/restart_feedback_compare_v1.py) 使用已认证的 Click 和 ItsDangerous 两项开发缺陷，各组各一次全新运行。第一轮 Prompt 成对一致；后续源码版本、刷新证据及版本说明随干预变化。两组相同模型、唯一片段替换协议、严格单 JSON 代码块解析、公开测试、独立评分、两次调用上限与 15,000 Token 预算；证据上限 6,000 字符、五项，未增加预算或使用私有评分反馈。

| 任务 | 继续修改候选 | 从起始源码重新修复 | 重启组 Controls |
| --- | --- | --- | --- |
| click-usage-empty | 通过 | 目标失败 | 通过 |
| itsdangerous-none-salt | 目标与控制测试失败 | 目标与控制测试失败 | 失败 |

两项重启均恢复起始精确字节，反馈事务均通过结构检查，没有预算停止或无效补丁。Click 只改变前缀空格与部分窄宽度处理，宽模式仍调用 `wrap_text` 处理空参数，最终未输出需要的用法文本。none-salt 从起始源码重新生成后，仍删除 `make_signer` / `iter_unsigners` 的方法级回退，并在构造函数将 `None` 改为固定默认盐值；重启没有阻止错误逻辑再次生成。

本轮 Qwen `qwen3.5:27b`、关闭思考，八次本地调用共 **35,012 Token**：原组 16,903，重启组 18,109。全体新请求用量完整，零 DeepSeek 调用。原组 Worker 合计约 66.75 秒，重启组约 100.33 秒；本地单次小样本不能作为稳定性能结论。最终两组 Controls 均为 1/2，未取得控制测试收益。

## 验证和决策

新增测试 **7 passed**，验证真实公开检查下的两种编辑起点、成功时不重启、版本/范围拒绝及 CRLF 字节恢复。Windows 全量 **1,176 passed、2 skipped，204.84 秒**；Ruff 通过。实验结束冻结哈希及模型身份校验通过，临时数据在 D 盘；没有重跑 Linux、容器、HTTP 验收。

结论：不能将此前失败简单归因为“在错误候选上继续修改”。当前模型在原始源码上仍生成相同类型的参数语义错误。两项任务已用于失败分析，各一次，不能证明所有任务重启都更差；但不支持采用此版本或追加同方向实验。

下一步应先关闭单例驱动的格式/上下文调整，归类历史语义失败并检查执行流程是否缺少可执行的定位证据，例如公开失败调用在源码中的参数取值和分支路径。只有找到区别于已做关系矩阵、修复假设与补丁历史的新信息缺口，再设计一个受控核心实验；不把再加一段提示词当成确定改进。

