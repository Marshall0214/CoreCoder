## 2. 当前问题清单与优先级

### P0：读取工具不能识别模块常量和导入绑定

- **已确认：**`read_symbol` 只索引函数、异步函数和类。源码中实际存在 `_ansi_reset_all = "\033[0m"`，也存在 `from ._compat import strip_ansi`，工具却返回 `symbol_not_found`。
- **影响：**模型想检查已有依赖，却得不到相应声明；“工具不支持该类型”被表现为“名称不存在”。这是第三轮进入编辑之前的直接阻塞。
- **下一步：**支持同一允许文件内的受限赋值/导入声明读取，区分本地定义、导入绑定、真正缺失与歧义。返回来源及版本信息；不自动追踪到禁止读取的 `_compat.py`。
- **验收：**覆盖常量、导入别名、真正不存在的名称和现有函数读取；再用同一案例、相同预算复测是否能进入编辑及验证。工具可读不等于修复必然成功。

代码依据：[读取器](../repairflow/issue_tools.py)。已有可选 `module-bindings-v1` 初始上下文策略能补入部分模块声明，但它与主动 `read_symbol` 是两条路径；第三轮使用 `baseline` 初始策略，不能说读取工具已经具备该能力。

### P1：查询失败后，模型没有有效改变策略

- **已确认：**第三轮反复读取 `_ansi_reset_all`，最后三次动作连续报错。停止保护正常生效，避免了无限循环。
- **尚未解决：**停止规则只能终止重复，不能帮助模型找到替代证据。当前也未证明模型能根据候选符号和错误提示自行恢复。
- **处理顺序：**先修复 P0，避免要求模型绕过工具本身的缺口；随后观察是否仍重复。若仍存在，再验证错误分类、替代动作提示或状态相关的重复抑制，暂不增加轮数。

### P1：补丁原文不准确，真实模型的重读恢复尚未验证

- **已确认：**第二轮两次返回的原文锚点不真实，严格校验正确拒绝了修改。
- **已有能力：**当前实现了结构化错误、重读要求、版本与唯一锚点校验；真实 Docker 脚本测试验证过“无效编辑 → 重读 → 有效编辑”。
- **证据缺口：**第三轮真实模型没有申请编辑，不能用脚本测试宣称模型已经学会恢复。
- **后续验收：**记录真实模型是否生成准确锚点、失败后是否读取当前原文及改正；分别报告工具链正确性与模型修复效果。

### P1：能应用补丁，仍可能没有修复问题

- **已确认：**第一轮引入未定义名称；第二次修改消除了新增异常，却回到原始缺陷状态。
- **含义：**消除当前报错、补丁可应用、通过语法检查，都不能替代目标行为与正常行为验证。信息缺失可能影响判断，但尚不能据此认定是唯一原因。
- **后续：**读取阻塞解除后，继续检查模型是否核实依赖、理解目标与保留行为；不把无依据的全局字符串清理等修改当作通用修复。

### P2：上下文重复传输，输入 Token 随步骤增长

- **已确认：**请求同时包含证据片段和近期 observation，读取到的源码可能重复出现。第三轮输入 37,584、输出 174；单次输入从 3,421 增至 7,764。
- **尚未确认：**重复内容具体占多少成本、压缩是否改善修复率，尚无对照。
- **后续：**考虑 observation 只留状态与证据引用，源码按版本去重；单独测量，避免与 P0 同轮改动后无法归因。当前总量 37,758 未耗尽 60,000 上限，不能把本轮失败归为预算不足。

代码依据：[循环与上下文组装](../repairflow/issue_agent.py)。

## 4. 评测与产品边界

1. **泛化证据不足。**旧 50 项反复用于开发，且仓库分布不均；当前新流程仅有一个 Issue 的三轮开发记录。需要后续新增并冻结未参与调优的任务，按仓库或缺陷家族分组；不能把重复运行次数当作新任务数。
2. **测试通过的范围有限。**旧任务采用项目编写的目标/正常行为检查，并非上游完整套件；当前 Click 案例的公开检查来自报告者预期，无独立隐藏评分。因此只能称通过约定公开检查、待人工审查，不能宣称普遍正确或上游认可。
3. **沙箱与评分可信性不同。**Docker 隔离执行不能保证同解释器内的测试绝不被候选代码影响。历史 47/50 评分早于 Docker 接入，也不能回溯表述为容器评测成绩。
4. **新旧入口尚未统一。**新 Issue 修复主要走 CLI；现有可信任务目录的服务/审批能力，不等于新 Issue 已接通完整 HTTP 审批流程。当前主动动作只有 `read_symbol`、`apply_patch`、`finish`，还不能描述为通用跨仓库自主搜索 Agent。
