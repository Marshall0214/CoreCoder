# retrieval-quality-v1：离线修复文件召回评测

日期：2026-10-04。新增 `python -m evals.retrieval_eval`，不调用模型、不运行候选代码、不修改任务工作区。默认覆盖现有 11 个人工任务，在 K=1/3/5/10 下共生成 44 份观察；三套任务分开汇总。

## 标签与隔离

标签为 reference.json 中实际修改的源码文件，按路径去重。标签在所有检索观察确定后才读取，仅供评分；参考补丁、隐藏测试及标签不进入查询、索引、证据构建或模型。索引依旧只扫描 workspace 内允许源码和公开文档。

这是 **修复目标文件的代理标签**，不是完整相关性标注：必要文档、调用入口和解释性依赖可能没有被参考补丁修改，等价修复也可能修改其他文件。因此不计算以所有未标注文件为负例的 Precision，不宣称得到完整 RAG 相关性评测。

## 指标口径

- **种子 Recall@K**：前 K 个唯一正分候选中命中的目标文件 / 全部目标文件。按首个 chunk 出现位置确定文件排名，文档也占候选位；不按源码单独重排，也不为凑满 K 加入零分文件。
- **MRR**：完整正分唯一文件排名中第一个目标文件的倒数排名，未召回计 0；它不随 K 截断，不表示多处缺陷全部覆盖。
- **扩展覆盖**：相同种子、深度上限、允许范围和索引规则下，忽略证据字符/文件数量预算的静态依赖闭包对目标的覆盖，仅为诊断视图。
- **实际证据覆盖**：当前 pipeline 的完整文件预算裁剪与扩展结果对目标的覆盖。大文件被丢弃时也不会继续沿其依赖扩展，与诊断闭包可以不同。

Recall 在任务内先计算，再按套件宏平均，每个任务等权。覆盖目标源码不代表引用有效、上下文足够、定位推理正确或补丁通过验收。目标源码均命中时继续增加 K 也可能只是增加噪声。

## 复跑

```powershell
python -m pytest tests/test_retrieval_eval.py -q
python -m pytest tests -q
python -m evals.retrieval_eval
python -m evals.retrieval_eval --suite evals/fixtures/localization-v1 --top-k 1 3 5 10 --dependency-depth 2 --max-chars 6000 --output .tmp/evals/retrieval-quality-replay
```

每次自动创建新目录，不覆盖旧结果。不加载 .env、无需模型凭据；当前 JSON 中复用的 RunConfig 模型字段为未调用的默认占位，不代表使用了远程模型。benchmark_eligible=false 表示它不参与模型修复成功率基准；结果用于检索诊断。
