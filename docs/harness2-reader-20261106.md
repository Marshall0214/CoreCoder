## 与原入口的区别

原入口把完整公开轨迹序列化成 `visible_files`，一次发送；压缩后仍超过 160,000 字符就无法进入策略合成。新 `indexed` 模式将原始证据复制为独立快照，先给任务、当前指导、候选公开终态及每个事件的文件 ID、哈希、字符位置，再让模型选择读取原文。

```text
公开上下文目录 → 哈希固定的证据快照 + 索引
→ 本地模型请求 read_evidence → 控制端校验并返回原文页
→ 模型继续读取 / 返回三份指导配置
→ 原有格式校验 → 写入本次候选 Harness
```

例如模型返回：

```json
{"action":"read_evidence","arguments":{"id":"e0007","offset":12000,"length":6000}}
```

这是 JSON 动作接口，沿用原生 Ollama JSON 输出，不依赖模型厂商的原生 Function Calling。执行器只接受索引中的 ID，偏移为从 0 开始的 Unicode 字符数；每页最多 6,000 字符，返回 `next_offset`、`eof`、原文总长与文件哈希。长事件可继续分页，没有原文页被静默截掉。

## 上下文与权限边界

- 始终保留任务、证据索引、候选公开终态与完整读取记录；从 0 读到 EOF、长度不超过 4,000 字符的小文件持续保留原文。其他分页只带最近 3 份不同结果及最近一次错误反馈，原文仍可重新读取。
- 动作请求、实际模型输入、模型响应、读取结果和错误均逐步落盘。对超长的已拒绝模型输出，当前上下文使用明确的归档描述，原响应文件保留；不声称缩减后的模型上下文等于完整 Trace。
- 索引按白名单接收公开上下文材料，包含原先遗漏的 `candidate.diff.txt`；不索引仓库 `source/` 导出，也不新增代码仓库读取权限。代码证据仍来自已产生的公开读取轨迹。
- 独立评分/隐藏检查目录被拒绝，链接与 Windows 重解析点被拒绝；不支持任意路径、Shell、网络工具或测试修改。索引和每份读取快照有哈希校验，来源目录后续变化不影响快照。
- 默认仍为 `inline`。新模式显式启用并写入新协议；已冻结批次不切换模式。每次编辑会话最多 20 次模型请求，包含读取与格式纠正，保留原 300 秒会话上限；这与修复执行最多 20 次公开反馈修正是两套计数。没有新增 Token 预算或输出 Token 截断。
