predicate 第二轮从 2048 Token 截断变为完整、可应用的 **417 Token** 补丁，但语义仍失败；

## 先离线验证，再真实运行

复用 [既有函数替换](function-replace-v1.md) 的版本、完整函数展示、唯一 AST 声明、
重复/重叠与唯一原文匹配检查，没有重新实现完整函数定位器。
此前协议仍需要模型生成完整函数与文档；新增 [执行体编辑器](experiments/body_block_edit_v1.py)
只在第二轮要求 `block_id + new_body`。块标识绑定当前文件哈希、函数及执行体范围，
编辑器用当前源码保留签名、装饰器、文档及缩进，重建函数后交给既有 lowering 和唯一匹配执行器。
不接受未展示/局部函数、过期版本、未知或重复块、重叠替换、重复签名/文档及不可编译代码。
不支持修改签名、默认参数、装饰器或文档；行内函数套件不作为可编辑块展示。

离线从历史截断回答中解析出已经完整输出的第一个 locate 编辑：原 old/new JSON 为
**3190 字符**，相同执行体协议为 **299 字符（减少 90.6%）**，程序重建后的 AST 与该片段一致。
这只验证一个完整片段的表达开销；未推断缺失的 replace 代码、未应用历史残缺补丁，
也不是整项 Token 节省或修复成果。离线新增模型调用为零。

离线检查支持后，运行 [五项配对入口](experiments/body_block_compare_v1.py)。两组各重新请求，
五对首轮 wire 请求和回答完全相同；第一轮、原检索证据及公开反馈内容保持原流程。
仅第二轮 system 输出协议与小型块目录改变，源代码字符上限仍为 6000、最多五段。
没有加入补齐依赖或采样策略，没有读取参考补丁或私有评分测试来构造模型输入。

## 失败解释与停止理由

- predicate 第二轮完整补丁已编译、应用，但把 windowed 填充值改为 `None` 后，
  仍把填充值传给用户 predicate；短输入的 `sum(items)` 抛出 `NoneType` 类型错误。
  本例修正了输出截断，却没有修正参数行为，不能再用输出截断解释这个候选的失败。
- none-salt 的 `new_body` 包含完整 `Signer.__init__`、`Serializer.__init__` 等函数。
  核对发现两个构造函数的参数 AST 实际不同于当前候选，并非只多了一层无变化的包装。
  剥离并忽略这些签名变化会改变模型提交的补丁，不能把这种处理冒充安全封装兼容。
  原协议允许这些修改；新协议不能表达，所以判为协议拒绝，不判为已应用后的行为失败。

本轮修改了输出协议及可表达编辑范围，而不只是 JSON 压缩；签名限制会阻止部分修复路径。
不能据五项证明块协议普遍无效，也没有证据支持继续追加提示或扩跑。
将原流程保留为默认，不将这个原型作为修复成功率提升写入简历。
