## 已确认的实现缺陷

public_api_context_v1.py 先把完整名称对应的方法设为 exact_description_symbol，再用下面的判断清理普通自然语言词：

```python
index.names[key].rsplit('.', 1)[-1] not in explicit
```

explicit_mentions 对点名方法返回完整名称，例如 HelpFormatter.write_usage；比较端却是 write_usage。由此该明确符号的优先级被删除。Context.invoke、numeric_range.__reversed__ 同理。目标仍可能因关键词排名偶然入选，但这三项实际没有入选。

这属于已确认的工程错误。应使用同一套符号解析结果判断显式引用，并确保明确目标在最终打包后仍存在。现有代码虽有 required/missing 信息，外层包装还丢弃了部分覆盖元数据；当前预检只验证原文、hash 与预算，不能发现“片段合法但目标缺失”。

另有两处覆盖不足：资源管理协议没有强制联动入口/退出方法；相等/hash 以及成员/index/长度等联合行为尚未完整映射到方法集合。当前公共 API 工厂词匹配和依赖扩展可能占据前五个片段，且反馈失败后仍重复检索同样的无关片段。

离线完整符号审计见 current-full-repair-v1-symbol-audit.json。50 项中 5 项有可解析的显式符号未被提供，其中 3 项失败，另外两项成功但遗漏的是 option、Result.output 等辅助符号。因此“所有描述符号都必须提供”过于粗糙，应区分明确修复主体与正常行为/调用示例中的辅助符号。

- click-shared-default：本轮主要提供 Command.get_params、to_info_dict、collect_usage_pieces、make_parser、format_options，未覆盖 Option.get_default 等默认值决策。首轮空 edits，第二轮思考截断。应先审计工厂定位及默认值实现覆盖。

## 新增成功的依据

- help-eagerness：从装饰器/构造函数上下文转为帮助选项实现上下文，首轮完成，历史首轮截断。
- default-map：提供 get_default 和 get_help_record，实际展示默认值的修复点可见。
- envvar：首轮通过旧公开/冻结检查，被新精确契约拒绝；第二轮将未激活返回值从 None 改为声明默认值的字符串，最终独立通过，累计 49,265 Token。该项有直接的验证拦截和反馈修正证据。
- prompt-suffix：同时提供 prompt 与 confirm 正文及 _build_prompt，覆盖两个公开入口；历史只通过公开检查，独立失败。
- remap-set：提供 remap 正文和默认 traversal 回调，历史主要给 OrderedMultiDict 方法。

这些结果说明局部选取和验证有价值。初始候选也重新采样，且模型为云端别名，不能把全部新增成功唯一归因于算法改动。
